# Portable village material textures

`tidewater.village-materials/2` binds the exported village geometry to its baked PBR inputs. The component refers to the village object and to one content-addressed `village-materials/1` asset, and uses the renderer profile `original-tidewater-village-v1`. Its visible streaming bounds match the village object so clients do not fetch tens of megabytes for a distant portal preview.

The asset contains fourteen level-zero RGBA8 maps: weathered wood albedo and normal/roughness/AO, paint-film normal/roughness/AO, corrugated-roof albedo and normal/roughness/AO, thatch albedo and normal/roughness/AO, stone albedo and normal/roughness/AO, worn-metal albedo and normal/roughness/AO, plus grime, rope, and net maps. The asset metadata records each map's dimensions, metre tile size, channel meaning, sampler, and mipmap profile. The browser expands the versioned deflate container, uploads the exact map bytes, and builds the box-filtered mip chains used by the original renderer. It loads the trusted renderer profile already shipped with the client; world assets never provide shader source or executable code.

The map bundle is produced from the same `VillageTextures` WGSL generators as the playable island by `npm run export:island`. Keep the packed bytes and their SHA-256 in the repository alongside `world-source.json`; this checked-in data is the serverable visual input and avoids requiring an author's GPU state at runtime. Re-export changes require byte-stability checks and matched camera comparisons against the original Tidewater village, beach, and mountain approaches. The GLB remains the geometry and collision representation; it is not a substitute for these maps.
